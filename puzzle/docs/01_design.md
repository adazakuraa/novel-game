## 1. ゲームルール（Bus Jam型：「おまちどう」）【確定・実装済み】

ルール本体はテーマと無関係（§6）。寿司テーマでは「盤面のお寿司の皿を、カウンターのお客さんの注文どおりに出す」見え方にする。

### 1.1 構成要素

| 要素 | 内容 |
|---|---|
| 皿の列 | W 列（4〜6）。各列は上から順に並んだ皿の山。上から rows 枚（3〜5）だけ見える。それより下の皿（1列あたり0〜2枚）は見えず、列の下に「あとN」と枚数だけ出す |
| 皿 | ネタ（色）を1つ持つ。**皿のふちの色**（赤・黄・緑・青・紫・黒）と**お寿司の形**（にぎり・玉子・巻物・軍艦・エビ・イカ）の両方で区別する |
| お客さん（注文） | 「この皿を n 枚ほしい」。n は 2〜4（1〜10面と31面は3で固定）。服の色と吹き出しの皿の絵で注文が分かる |
| カウンター | お客さんが1人（1〜20面など）または2人同時（21面以降の多く）座る |
| 行列 | このあとのお客さんの順番と注文。**全員を常に表示** |
| 置き台 | 合わない皿を一時的に置く場所。数 K（3〜4） |

### 1.2 操作と処理（タップのみ）

1. 皿をタップする。**各列のいちばん上の皿**だけ取れる（予約札が残っている皿は取れない）。
2. 取った皿は：
   - 座っているお客さんの注文と同じ → そのお客さんへ（2人とも同じなら左の人へ）
   - 違う → 置き台へ。**置き台がいっぱいなら取れない**（揺れるだけ。負けにはならない）
3. 取った列は1段上がり、下から次の皿が見えるようになる。
4. 注文の枚数がそろうと、お客さんが帰り、行列から次のお客さんが座る。
5. 座ったお客さんの注文に合う皿が置き台にあれば、**自動で**渡す（左から順）。これで注文がそろえば、さらに次へ進む——**連鎖**。

取れる手は少し浮いて白く光らせる。取れるはずの位置にあるのに取れない皿（予約札、置き台がいっぱいで注文に合わない）だけ薄くする。下の段の皿は暗くしない（色が見分けにくくなるため）。

### 1.3 クリアとゲームオーバー

- **クリア**：全員の注文を出し終える。
- **ゲームオーバー（唯一の失敗）**：打てる手が1つも無い。画面には理由（「置き台がいっぱいで、渡せるお皿がありません」／「取れるお皿がありません」）を出す。
- もうクリアできない局面になっても、手が残っている間は知らせない。手数・時間の制限は無い。やり直しは無料・無制限、一手戻すは無い。

### 1.4 考えどころ

- どの列を掘ると、いまと次のお客さんの皿にたどり着けるか（盤面整理）
- 置き台に何を置くか。置いた皿が後のお客さんで一気に連鎖するように（効率・連鎖）
- お客さんが2人のとき、どちらの注文を先にそろえるか
- 見えない皿に頼らない手順を組む（見えている皿だけで必ず解ける）

### 1.5 ギミック【実装済み】

| ステージ | 追加要素 | ルール |
|---|---|---|
| 1〜10 | 基本 | 注文は3枚固定、お客さんは1人。3面から下からの補充が入る |
| 11〜20 | 注文の枚数がいろいろ | お客さんごとに 2〜4 枚 |
| 21〜30 | お客さんが2人 | カウンターに2人同時に座る |
| 31〜40 | 予約札 | 札の人数だけお客さんが帰るまで取れない（残り人数を表示）。最初から見えている皿にだけ付く |
| 41〜50 | 6列 | 列が6列になる |
| 51〜60 | 総仕上げ | 組み合わせ。6色 |

見送り：柱・のれん（列が下から補充される形では役目がなくなったため。v0.3 まで使用）。

## 2. 画面構成 【実装済み】

スマホ縦持ちを基準に、片手の親指で全操作が届く配置。横持ち・PC では盤面を中央寄せで拡大する。

```
┌──────────────────────────┐
│ ←      ステージ 12          ↻   │  上部バー（↻ は途中なら確認あり）
├──────────────────────────┤
│  (客 赤皿 1/3) [赤][  ][  ]      │  カウンター（1人、または2段で2人）
│  このあと: 黄×2 緑×3 赤×4 …      │  行列（全員・欲しい皿の絵と枚数つき）
├──────────────────────────┤
│  置き台  [青][  ][  ]            │  K 個
├──────── カウンターへ ────────┤
│   赤 黄 黄 緑 黄                 │  ← いちばん上の皿だけ取れる（白く光る）
│   ・ 緑 青 黄 黄                 │
│   ・ 黄 赤 青 黄                 │  皿の列：上から rows 段だけ見える
│  あと2      あと1     あと2      │  見えない皿は枚数だけ
└──────────────────────────┘
```

| 画面 | 内容 |
|---|---|
| タイトル | ゲーム名、「つづきから（ステージ N）」、「ステージを選ぶ」、設定。将来はここでモードを選ぶ |
| ステージ選択 | 番号の格子。クリア済み／挑戦可能（次の1つ）／未解放の3状態。クリア済みはいつでも再挑戦可 |
| プレイ | 上図。取れる皿が分かる表示は「ルールの可視化」でありヒントではない（どれを取るべきかは示さない） |
| クリア | 皿が下がる演出→「次のステージへ」。評価（星など）は無し |
| ゲームオーバー | 理由（置き台がいっぱい／取れる皿が無い）、「最初からやり直す」「ステージ選択」 |
| 設定 | 演出の速さ（標準／速い／なし）、進行データの消去 |

見分けやすさと色覚への配慮：皿のふちを回転寿司の色皿のように、はっきり違う6色（赤・黄・緑・青・紫・黒）にし、お寿司の形もネタごとに変える（にぎり・玉子・巻物・軍艦・しっぽ付きのエビ・切れ目のあるイカ）。色が分かりにくくても形で区別できる。小さな文字の札は認知の負担になるのでやめた。

演出の方針：
- 皿がタップされると、列の上へ抜けてお客さんの前／置き台へ運ばれ、列が1段せり上がる。
- 注文がそろうとお客さんと皿が右へ去り、行列から次のお客さんが進み出る。連鎖時は1段ごとに少し間を置く。
- 演出中も次のタップを受け付ける（タップされたら演出を早送りしてから次の手を処理する）。待たせない。

## 3. 進行・保存 【実装済み】

- ステージは 1 から順に解放（クリアで次が開く）。クリアしたかどうかだけを記録する。
- 保存はブラウザの localStorage（キー `omachido.v1`）。アカウント不要。保存できない環境でも遊べる。
- 途中の手順も自動保存し、アプリを閉じても続きから遊べる（ルールが決定的なので、手順を再生すれば同じ局面に戻る）。
- やり込み＝全60ステージクリア。
- 未実装：データの書き出し／読み込み。

## 4. 技術構成 【実装済み】

既存 RPG と同じ **Vite + TypeScript + Preact + Vitest**（無料・ビルド後は静的ファイルのみ・GitHub Pages で配信）。外部サービス・有料 API は使わない。

描画は DOM 要素＋CSS（グラデーション・影・ハイライトで立体感を出した 2D）。絵の素材ファイルは使わず、寿司や客はコードで描く（SVG）。Canvas より、Playwright での UI テストと当たり判定が簡単なため。

### 4.1 共通部分とゲーム固有部分の分離

```
puzzle/
  src/
    core/            共通：ゲームモードの型、ステージ管理、進行、保存、乱数、テーマの型
    modes/
      queue/         Bus Jam型：rules.ts（純粋なルール）、solver.ts、generator.ts、metrics.ts、view/
      （将来）sort/  Sushi Heaven型
    themes/
      sushi/         見た目だけ（ネタの絵・色・名前）
      （将来）bus/
    ui/              タイトル・ステージ選択・設定・共通の結果画面
  stages/            確定したステージデータ（queue.json）
  tools/             ステージ生成（gen-queue.ts）
  tests/             単体・全ステージ検証・自動プレイ（Vitest）
  e2e/               UI テスト（Playwright）
  docs/
```

各モードは共通の型を満たす：

```ts
interface GameMode<Stage, State, Move> {   // src/core/mode.ts
  id: string;
  name: string;
  init(stage: Stage): State;
  legalMoves(state: State): Move[];
  apply(state: State, move: Move): State | null;   // 不正な手は null
  status(state: State): 'playing' | 'cleared' | 'full' | 'stuck';
}
// 途中保存は「手順の配列」で行う（どのモードでも決定的なので共通化できる）
// Bus Jam型の apply は演出用に途中経過（Frame）も返せる
```

ルールは副作用の無い純粋な関数にし、UI・ソルバー・テストがまったく同じルールの実装を使う（表示と検証でルールがずれない）。

## 5. ステージ生成・解法探索・品質保証 【実装済み】（重要）

### 5.1 方針
- **ステージは開発時に生成・検証して固定データにする**（全員が同じ盤面。プレイ中の乱数はゼロ）。
- 生成はシード付き乱数で再現可能にする。ステージを作り直しても同じ結果になる。
- 「開発者が手で解けた」ことを品質の根拠にしない。**全ステージを CI で毎回、完全なソルバーで検証**する。

### 5.2 「見えている情報だけで解ける」ことの保証（`src/modes/queue/robust.ts`）

各列の rows 枚より下の皿は見えない。そこで、見えない皿が見えるようになるたびに、その色を「意地悪な相手」が残りの見えない皿の中から選ぶと考え、それでも勝てる打ち方があるかを調べる（勝ち負けの総当たり。自分の手は「どれか1つで勝てればよい」、相手の色選びは「どれを選ばれても勝てる」）。

- 局面は「プレイヤーに見えている情報」（各列の見えている皿・各列の残り枚数・見えない皿の色の内訳・席・置き台・行列）だけで記憶する。
- 勝てる打ち方があれば、見えない皿の実際の並びがどうであっても、見えている情報だけで正しく考えれば必ずクリアできる＝運では詰まない。
- ルール本体を二重に書かないよう、見えない皿どうしの色を入れ替えた局面を作り、本物のルールで進める。
- 単体テストで、見えない皿の全並びを素朴に総当たりした結果と一致することを確かめている。
- この保証は強い条件なので、見えない皿が多い盤面ではほとんど成り立たない（相手が、次のお客さんの欲しい皿を全部の列の底に埋められるため）。試算では1列あたり見えない皿が1〜2枚なら十分な数の盤面が作れた。そこで「見える段数＋0〜2枚」を基本にした。

実際の並びでの解法（再生テスト・UI テスト用）は、ふつうのソルバー（`solver.ts`：深さ優先探索＋局面の記憶）で求める。

### 5.3 品質指標と採用基準（`src/modes/queue/specs.ts`）

| 指標 | 意味 | 基準 |
|---|---|---|
| 見えている情報だけで解けるか | §5.2 | 必須 |
| 難易度：正解の手の割合 | 見えている情報だけで勝てる局面で、打てる手のうち勝ち筋に残る手の割合（手が1つしかない局面は除く）を、勝ち筋の中を20回無作為に歩いて平均したもの。低いほど難しい | ステージごとの目標値 ±0.03（1面 0.95 → 30面 0.77 → 60面 0.71。各ギミックの導入面は少しやさしく） |
| 本質的に異なる解法の数 | どの皿を置き台に通したかの組が違う解法の数（実際の並びで、手の順番を変えて30回解いて数える） | 1〜2面は1以上、3〜10面は2以上、以降3以上 |
| 序盤の自由度 | 最初の一手のうち、見えている情報だけで勝ち筋に残れる手の数 | 2以上（1本道の禁止） |
| 罠の深さ | 素直な打ち手が詰みに入った局面から、実際にゲームオーバーになるまでに打てる最大の手数 | 1〜20面 10手以下、21〜50面 15手以下、51〜60面 20手以下 |
| 参考 | 素直な打ち手・何も考えない打ち手の勝率、解法での置き台の余裕 | 記録のみ |

v0.3 までの難易度の物差し（素直な打ち手の勝率）は、列が下から補充される形では序盤からほぼ0%になり差が付かなくなったため、「正解の手の割合」に替えた。

生成ツールは設計表の各行について、シードを変えて候補を作り、基準を満たした候補のうち難易度が目標に最も近いものを採用する。採用時の計測シードをステージデータに記録し、テストで同じ計測を再現して基準を確かめる。範囲を分けて並列に生成できる（`PART=1`、`merge`）。

### 5.4 v0.4（60面）の計測結果（要約）

- 全60面：見えている情報だけで解ける（見えない皿がどんな並びでも）。皿は1面9枚 → 50面以降は27〜37枚。
- 正解の手の割合：1面 0.94 → 10面 0.84 → 20面 0.78 → 30面 0.77 → 40面 0.78 → 50面 0.76 → 60面 0.70（各帯の最初は少しやさしい）。v0.3 の13面に当たる難しさ（素直な打ち手の勝率 約6割）は、v0.4 では5面あたりで超える。
- 素直な打ち手の勝率：4面以降はおおむね0〜25%、16面以降はほぼ0〜6%。
- 異なる解法：3面以降は4通り以上（多くは20通り以上）。罠の深さ：最大17手（57面）。

## 6. テーマの分離

ルールが知っているのは「色番号」と「列の並び」だけ。テーマは色番号→見た目（寿司ネタ／バスの色と乗客）、文言（お客さん／バス、置き台／駐車場）を割り当てる。将来のバステーマは見た目と文言の差し替えだけで追加できる。
