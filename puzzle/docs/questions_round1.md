# 質問リスト 第1回（2026-11-16）

回答形式の例：`Q1: A`、`Q3: B（ただし〜）`。★＝実装の前に決めたいもの。それ以外は「任せる」でも可。
（推奨）＝設計者の推奨案。理由は `01_design.md` を参照。

- **Q1★ 置き場所**（P-01）：
  **A 同じリポジトリの `puzzle/` に別アプリとして作り、`…github.io/novel-game/puzzle/` で公開。RPG はそのまま（推奨）**
  / B 別リポジトリ（GitHub 上で空のリポジトリを作ってもらい、こちらに追加する）
  / C RPG を置き換える
- **Q2★ 基本ルール**（§1）：この内容でよいか。特に「待ち席が満席のときは合わない客をタップできないだけで、負けは手詰まりのときのみ」（P-02）
- **Q3★ 一手戻す**（P-04）：
  A 無し（要件どおり、最初からのやり直しのみ）
  / **B 何手でも戻せる（推奨：誤タップ1回で数分ぶんをやり直すストレスを無くす。考える楽しさは残る）**
  / C 直前の1手だけ戻せる
- **Q4★ もう解けなくなったことを知らせるか**（P-05）：
  **A 知らせない。実際に打つ手が無くなったときだけ「手詰まり」（推奨：ヒントにならない）**
  / B 解けなくなった時点で知らせる（「この先クリアできません」）
- **Q5★ ステージの作り方**：
  **A 開発時に生成・検証して固定（全員同じ盤面）。初期 60 ステージ程度（推奨）**
  / B 毎回ランダム生成（その場で解けることを検証）
  / C A に加えて、クリア後のおまけとして毎回ランダムのモード
- **Q6 盤面の主役**：
  **A お客さん（注文のネタの札や色で区別）が席へ向かう（推奨：飲食店らしさ）**
  / B 寿司そのものが皿（舟）へ乗る
- **Q7 ゲーム名**：希望があれば。無ければ仮称で進め、後で案を出す
- **Q8 Sushi Heaven型**：想定しているルールの概要（例：何を動かし、何をそろえると消えるか）。急ぎではない
- **Q9 ギミック**（§1.5）：入れたくないもの・入れたいものがあれば
